# 待提交队列与智能助手

## 两种提交入口

| 入口 | 行为 |
|---|---|
| 助手工具 `javcloud_submit` | 只入队，立即返回“已添加至队列：N 条（前面还有 M 条）”，由 10 秒服务在后台消化 |
| HTTP `POST /api/v1/plugin/JavCloudDownload/submit` | 同步提交，本次调用内完成取种与 115 离线提交；可选 `wait_seconds`、`upgrade`、`force` |

批量下载走助手工具；需要立即拿到每个番号的提交结果时走 HTTP。

## 助手工具

### javcloud_submit

参数 `codes`：字符串或数组。字符串可用逗号、中文逗号、换行分隔。

返回 JSON：

| 字段 | 含义 |
|---|---|
| `ok` | 是否受理 |
| `batch_id` | 本次提交的批次 ID |
| `queued` | 新入队条数 |
| `queue_size` | 入队后队列总长度 |
| `skipped` | 已在队列或处理中的番号 |
| `invalid` | 无法识别的番号 |
| `message` | 给用户看的一句话，助手应原样转述 |

同一批提交共用一个 `batch_id`。番号会归一化，例如 `abc_123` → `ABC-123`。

### javcloud_tasks

- `code`：可选，只查该番号。
- `limit`：默认 20，范围 1–100。

返回最近任务、`queued_count` 和 `queued`（含排队位置 `position`）。不返回磁力链接。

## 队列行为

- 上限 **1000** 条；超出时整次调用拒绝，不做部分入队。
- 与队列内、进行中的番号去重，重复的放进 `skipped`。
- 定时服务每 **10 秒** 一轮，每轮最多提交 **5** 条，先进先出。
- 队列和批次记录随任务一起持久化，重启后恢复；进行中记录和未结算批次不会被历史裁剪丢掉。

## 批次汇总

同一 `batch_id` 内：

- 不逐条发“下载完成”“失败”通知；
- 记录全部进入终态（`organized` / `moved` / `skipped` / `failed`）后，发一条：

```text
标题：番号云下载批量完成：10 条
本次提交 10 条：完成 5 条，失败 2 条，跳过 3 条
失败：MXGS-784（未找到磁力）；MEK-008（所有候选都没有可用视频）
```

失败明细最多列 20 条，超出写“等 N 条”；原因压成一句并截断到 60 字。
汇总发送失败时下一轮重试；已通知的批次只保留最近 20 个。

汇总走插件通知，不会出现在助手的对话回复里。助手只负责在提交时转述入队结果。

## 任务状态

| 状态 | 含义 |
|---|---|
| `pending` / `submitted` | 已创建 / 已提交 115 离线 |
| `downloading` | 115 下载中 |
| `finished` | 下载完成，整理中 |
| `organized` | 整理完成，未移动 |
| `moved` | 已移入库目录 |
| `skipped` | 跳过（库内已有等） |
| `failed` | 失败 |

`organized` / `moved` / `skipped` / `failed` 为终态。

## 边界

- 番号搜不到属于正常失败，会写进批次汇总，不自动重试。
- 目录里没有可用视频（如只有 `.iso` 和广告）时，整理阶段直接换下一条候选，最多 3 条。
- 队列里的条目在提交前不占用 115；插件重启后继续消化。
