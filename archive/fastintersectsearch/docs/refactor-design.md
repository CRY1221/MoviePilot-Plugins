# 极速搜索重构方案

日期：2026-10-12。基线：插件 `fc9a27014939b642d483f5848e6246b501388469` / 2.6.0；MoviePilot `v3.1.4` / `09f62ff87e196df9e39a6422f23c23860610d96a`。设计依据包括本地固定版本源码、MCP 只读记录及用户转述的实例助手报告，三者不混作同一证据来源。

## 1. 已确定的目标与职责

保留跨站并行、同站排队、分页与流式返回，覆盖网页、TG 等通知搜索、Agent 与新订阅首搜。用户确认这些入口都慢。插件负责请求调度；规则选择、过滤、媒体识别、优先级、完整包/分集下载和订阅结算由 MP 持有。插件不得猜规则组、宽松覆盖匹配拒绝、给全集加分、复活被规则拒绝的资源。

选择“重做搜索调度适配层，复用 MP 业务层”。旧业务入口整段替换与首订预取后直接 submit 一并撤除。仅修复方法绑定不足以安全恢复订阅：旧预取一旦可运行，仍可能第一页即提交散集。

## 2. 资料完整度判断

这里的 95% 指**实现前的设计资料完整度**，不是代码进度、测试通过率或上线成熟度。以下决定实现方向的资料已从固定源码核验：

| 资料项 | 核验结论与依据 |
|---|---|
| 入口范围 | API → SearchChain；TG → process；Agent 原生 API / 独立工具；影视订阅 → SearchScan |
| 原生并发 | provider.py 同步共享线程池、pagination.py 异步跨站并发；并非全部原生串行 |
| 网页调度短板 | manual.py::_read_pages 同站关键词按全站轮次等齐；可改为各站独立 FIFO |
| 普通精确搜索等待 | execution.py::_keyword_delay 每轮别名间随机等待 1–10 秒；保留关键词和原状态机 |
| 规则职责 | plan 携带调用方规则；result.py / ChainBase.filter_torrents 交系统模块；None 与 [] 语义不同 |
| 排序职责 | TorrentHelper.sort_torrents 还读取 TorrentsPriority；不能自行只按 pri_order 排序 |
| 分页合同 | 普通自动页数、Web 单页 source token/签名、订阅每源最多 20 页分别处理 |
| 首订身份 | TaskRunner 持有 task.source；execution 只有 task_id/task_lease/lease.subscription_id，不能按标题猜 |
| 订阅状态 | SearchScan.step/ready/choose/checkpoint/run 均归原生；只并发单页网络 I/O |
| 完整包 | 整季缺失/full 等来源收集；smart 部分缺集不保证深页最优；下载链仍做整包/集数检查 |
| 频控 | 插件默认同站 5 秒；保留原生站点 limit_seconds、自动订阅至少 10 秒及错误冷却 |
| 源扩展 | get_module/search_torrents 是额外单页源，不能替代 PT 抓取；否则重复请求且失去分页事实 |
| 取消与线程 | 原生 manual._offload 取消等待真实线程终态；并发 worker 不写扫描状态或调用下载 |
| 音乐 | 元数据目录不同，但资源 execution/result 部分共用；音乐原样透传，影视演唱会/歌舞剧按实体类型处理 |
| 参数与缓存 | 保持 area/no_exists/season/规则/过滤器原样；插件工具 cache_local=False；Web 最终排序与缓存顺序一致 |
| 生命周期 | 原函数保存在普通记录对象；只卸载本实例持有的包装器；停止、重载、他方 Hook 的行为要验证 |
| 工具 | 原工具无显式输入 schema；require_complete/en_title 原承诺未实现；新工具必须明示能力与参数错误 |
| 发布 | V3 市场支持 v3/v2/v1 回退；新增 v3 包，V2 冻结留作历史，不把目录迁移误当故障修复 |

上述资料足以进入本地实现，工程判断达到约 95% 以上。尚未独立取得容器关键文件哈希；原生同条件耗时、真实 Web/TG 联调和视频歌舞剧样本仍需在验收阶段补充。它们限制兼容/性能结论，不阻止用已固定源码实现、离线测试；不得预告加速倍数或声称线上已通过。

## 3. 三条调度路径

### 网页手动分页

只适配 `manual._read_pages(manual, keys, page)`，保持 `(key, facts, torrents)` 输出。按真实站点分组，组内关键词 FIFO，各站独立推进；复用原 `_iter_site_page_results` 有界调度和 `_offload(manual.read, key, page)`。原 `manual.read` 仍决定上一页摘要恢复、实际页号、has_more/error；原 `_page_events` 仍构造预览、最终过滤、SSE 和首页缓存。不得固定 page=0 或伪造 can_continue。

### TG / Agent / 非手动网页搜索

保留原 SearchChain 入口与 `SearchExecutionOwner` 状态机。通过薄包装识别当前影视请求的作用域；仅在逐站统一间隔已经生效、且确认没有额外插件搜索源时，去掉 1–10 秒的整轮随机等待。第三方插件源存在或无法确认时保留该等待，以免绕开这些来源的节奏。音乐无此优化。

原关键词列表、别名停止条件、每轮累计解析与参数传递保持原样。网络请求与当前原生流事件并行推进；预览和最终结果保持原生状态标记。将过滤提到每批之前会改变累计规则/回调语义，未经等价验证不做这种移动。

### 新订阅

在持有真实 task 的 TaskRunner 边界传递只读 scope，要求 `source=new`、task/lease/subscription ID 与当前扫描一致，支持同一首订任务的延后恢复；不能只看 state=N（原生延后清理后也可能变 R）。

窄包 `_advance_sources`：仅预取本轮已有来源、每站一个当前页，经**原 `SearchSources.fetch`** 获取完整 ScanPage。原 `step` 顺序消费网络结果，继续原 ready/choose/checkpoint/submit。网络 worker 不改 collection/cursor/live/retry，不自行结算目标。页号从 cursor 只读投影，不提前调用会修改 refresh_pending 的 page_to_request；消费前比对页号、预算对象和执行代际。候选恢复重新拉取原页不得误用普通推进预取。

超时/取消/60 秒时间片结束时，取消尚未开始的预取，等待已开始请求释放预算；丢弃未消费内存结果，不把它们写入检查点或提交。可能发生有限额外预取，需统计数量；不声称与串行原生网络请求数始终逐条相等。取消、延期或已发生提交后禁止重新从头执行整轮“回退”。

## 4. 并行与流式的具体含义

- 不同站点可并发，同站关键词/翻页串行，慢站不阻塞其他站继续处理其已获准请求。
- 资源与进度可持续反馈；中间结果尚未完成全部约束时保持 candidate 状态。最终结果由 MP 系统规则/匹配/排序收敛，网络到达先后不得成为优先级。
- 订阅的流式含义是持续收集与处理页面，下载提交时机仍由原生 ready 屏障决定，不能用“首个结果出现”代替“可下载”。

## 5. 共享站点保护

仅在 SearchChain 的站点资源调用边界包装同步/异步方法，不替换全局 ChainBase，避免影响下载链内部行为。使用线程安全、跨 event loop 共用的站点门禁；单站一个真实在途请求，下一次开始不早于插件间隔与原站点间隔。保留更严格的订阅预算/退避；不写用户站点配置。等待可取消；异步取消不能提前放开仍在运行的同步请求容量。

记录实际请求耗时与排队等待分开；成功空结果与失败分开。指标失败不得把业务成功改成失败。多 MP 容器之间没有共享插件锁，不作分布式频控保证。

## 6. 系统规则与标题结果

插件不拥有任何规则解释器。影视精准搜索和订阅沿用完整原生参数及处理。标题模糊搜索沿用 SearchFilterRuleGroups，不能虚构已识别媒体身份。若需要标题结果跨站最终重排，只调用 `TorrentHelper.sort_torrents`，并同步最终事件、缓存与选择索引；不重建丢字段的 Context，不在订阅候选池做 top-k 截断。此展示适配与调度代码分开测试。

## 7. 工具、配置和兼容

保留 `FastIntersectSearch` / 极速搜索 / `fast_intersect_search` 身份，提供显式输入 schema。精准 ID 与标题查询合同区分，原生不支持的组合明确拒绝；所有规则仍走原生。TopK 只在工具最终结果展示时裁剪，不影响搜索请求、过滤或订阅；不写网页最近搜索缓存。保留旧字段兼容说明，`require_complete` 不得默默承诺完整包；无法落实的旧参数在 I/O 前明确返回不支持。

保留原 Vuetify JSON 页面及数据迁移入口。首订、双语、超时、间隔六个旧配置逐项说明新语义，未启用的功能不可在页面声称已启用。取消、超时、无结果、接口不兼容提供明确状态。

宿主私有引用集中在一个版本适配模块。安装前核验所有必须函数的同步/异步/生成器类型和签名；失败则不安装任何部分 Hook。包装器不覆盖后安装的第三方 Hook；无法安全解开旧版本闭包时要求正常重启，不能强行写回一个猜测的原方法。首版不自动部署或修改 MP 全局配置。

## 8. 实施与验收

实施顺序是依赖顺序，不代表把重构做到 95%：先新 V3 包与兼容生命周期，再共享门禁/Web 调度/原生工具适配，再首订当前页预取，最后统一回归与独立审查。

必须离线覆盖：原生方法 self 绑定；原生参数完整性；规则拒绝不复活；后页/跨站完整包；smart/full/single_page；new/fallback/恢复身份；影视/音乐/演唱会；页面 source/page/error；同站同步异步混合并发；客户端取消/停用/重载；借用宿主线程的真实收口；站点错误和超时；工具 schema/TopK/非法参数；最终排序与缓存一致。只在网络边界模拟返回，复用固定内核方法作对照，不能把全部被测业务用假结果代替。

上线前单独验证：容器合同、插件冷启动及停用恢复、Web/TG/Agent 无下载联调。订阅回归先用替身下载器离线验证；真实订阅会产生下载副作用，不用它补单元测试。性能以相同站点、关键词、页预算、规则、缓存条件对比首结果/最终完成/实际请求数/过滤识别耗时；未取得数据前只报告已证实的调度变化。

## 9. 旧摸底材料勘误

Doctor 的六条命中里包含我们读 execution 后写入日志的工具结果回显，它们不是六次新的订阅失败。2026-10-11 17:07 UTC 与 2026-10-12 01:07 中国时间对应；17:50 UTC 与次日01:50也对应，助手未声称01:50是最后一次失败。不同摘要样本不能制造时序矛盾。智能助手无完整traceback，且容器行号与公开源码少数不同，仍保留来源限制。

音乐不是完全独立的一套资源搜索循环；共享执行/结果处理需有类型边界。系统规则过滤也不等于下载决策：完整包保护依赖扫描就绪和下载链。材料中的“全部恢复调用存在绑定问题”是代码结论；线上直接确认的异常是SearchScan，不能扩称每个入口都实测失败。
